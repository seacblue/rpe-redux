# 安全模型

扩展运行在不可信沙箱中。宿主只暴露按能力授权的异步消息桥，包代码通过声明式 UI 和 `context.api` 工作。

## 运行边界

| 资源                       | 包是否可访问 | 说明                                          |
| -------------------------- | ------------ | --------------------------------------------- |
| 宿主 DOM / React 树        | 否           | 只能提交声明式节点树                          |
| Tauri IPC / `window.redux` | 否           | 桥接层在包加载前屏蔽                          |
| 网络                       | 否           | `fetch`、`XMLHttpRequest`、`WebSocket` 不可用 |
| 文件系统                   | 否           | 文档保存和资源写入走宿主流程                  |
| Worker / 子帧              | 否           | 不能创建新的执行上下文                        |
| `context.api`              | 是           | 异步、能力门控、返回克隆数据                  |
| `context.ui`               | 是           | 通知、对话框、面板、侧栏、覆盖层              |
| `context.storage`          | 是           | owner 作用域字符串存储                        |

包的活动范围是 `context.api`、`context.ui`、`context.events`、`context.storage`、`context.timers`、`context.styles` 和它自己注册的脚本/表面。

## 资源预算

| 资源      | 上限                         | 行为           |
| --------- | ---------------------------- | -------------- |
| 入口源码  | 2 MB                         | 加载失败       |
| 脚本      | 64 个活跃                    | 注册抛错       |
| 事件订阅  | 128 个                       | 注册抛错       |
| 定时器    | 64 个活跃，最小间隔 16 ms    | 抛错或钳制     |
| 样式表    | 32 张，每张 100 KB           | 注册抛错       |
| 存储 key  | 128 字符                     | 抛错           |
| 存储值    | 256 KB UTF-8                 | 抛错           |
| 声明式 UI | 256 节点，16 层              | 超出部分截断   |
| 图片      | 512 KB                       | 选择器拒绝     |
| 单次桥接  | 32 层 / 500,000 节点 / 16 MB | `bridge.limit` |
| 回调失败  | 30 秒内 5 次                 | 自动停用       |

失败预算按 30 秒滚动窗口计数。扩展被停用后，列表保留失败原因和最多 12 条最近错误。长任务使用 `ui.progress`，重复任务使用 `context.timers` 并遵守最小间隔。

## 信任与同意

| 状态               | 含义                         |
| ------------------ | ---------------------------- |
| `builtin`          | 与随包分发的规范摘要完全匹配 |
| `local-trusted`    | 本地来源且用户已确认         |
| `external-pending` | 外部来源，等待用户确认       |
| `blocked`          | 被策略或安全模式阻断         |

`author`、`license`、`homepage` 和 `repository` 只是元数据，不产生信任。GitHub / marketplace 安装会先下载清单、入口和声明的翻译文件，展示能力、版本、来源 commit 和文件列表，确认后才写入受管目录。包字节变化会让同意变为 `stale`，需要重新确认。

## 样式作用域

`context.styles.add(cssText)` 由宿主包进所有者作用域：

```css
@scope ([data-redux-extension-scope="<owner>"]) {
  /* package rules */
}
```

样式表可以命中本包的面板或覆盖层。以下构造会被拒绝：

- `:root`、`:host`、`html`、`body`、`*` 和 `url()`。
- `@keyframes`、`@font-face`、`@property`、`@counter-style`、`@page`。
- `@import`、`@namespace`、嵌套 `@scope`。
- 不平衡的花括号或未闭合的字符串/注释。

样式表不能读取数据、选择宿主节点或加载外部资源。

## 文档与文件

- `api.document.save` 始终使用宿主保存流程；包传入的 `path` 被能力门丢弃。
- 包不能创建或覆盖任意目录中的文件。
- 导出文本由宿主提供的文档导出流程写入；扩展没有通用的“写任意路径”操作。
- 资源写入需要 `assets.write`（敏感），只作用于当前项目或曲库声明的对象。
- 本地路径、令牌和用户隐私不写入通知、错误消息或 `context.storage`。

## 供应链

- 从固定 commit 或 release 安装，避免跟随可变分支。
- 审查入口文件和 `manifest.json` 的能力列表。
- 扩展只通过声明式清单和入口加载，不执行安装脚本。
- 发布前在干净配置文件中测试：切换亮/暗主题、缩放到 150%、只用键盘操作。
- 发现可疑行为时先停用扩展，再检查扩展列表的最近错误和来源。

## 审计与恢复

| 场景             | 操作                                           |
| ---------------- | ---------------------------------------------- |
| 扩展被自动停用   | 打开扩展列表查看最近错误和失败计数             |
| 同意变为 `stale` | 重新审查入口与能力，再确认新指纹               |
| 样式表被拒绝     | 检查 `@scope` 禁止的构造、花括号和字符串       |
| 发布前验证       | 在干净配置文件中启用，切换主题、DPI 和键盘操作 |
| 发现异常行为     | 先停用扩展，再检查来源、版本和最近错误         |
| 需要回滚         | 卸载或替换包目录，宿主按 owner 清理注册        |

审计时保留包 id、版本、来源 commit 和失败动作；这些信息足以定位是权限、运行时还是资源预算问题。
