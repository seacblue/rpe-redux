# Fixed-BPM detector evaluation methodology

The accepted evaluation set is generated by the project training script. Each case has one fixed BPM and one phase, so the expected result is unambiguous and the evaluation does not require bundling any media or chart files.

## Validation dimensions

- BPM is sampled continuously across 70–240 BPM, including non-integer values.
- Phase is sampled independently and is measured as beat-zero offset.
- Accents, transient lengths, background tones, and noise are varied.
- Short and long fixed-duration windows are included.
- Half- and third-beat alias candidates are included in the scorer checks.

The validation run is deterministic: the seed, generator, frontend, model, candidate search, and metric calculation are all in `scripts/trainFixedBeatModel.py`.

## Current result

The current self-contained run evaluated 256 held-out generated examples after 900 optimization steps:

| Metric                     |    Result |
| -------------------------- | --------: |
| Median absolute BPM error  | 0.151 BPM |
| P95 absolute BPM error     | 0.346 BPM |
| Maximum absolute BPM error | 1.033 BPM |
| Frame precision            |     0.992 |
| Frame recall               |     0.987 |
| Frame F1                   |     0.990 |

The production path then applies raw-attack refitting for the final continuous offset and returns one fixed BPM/offset pair. Variable BPM and meter inference are outside the feature contract.
